医療機関向け事業部にて、複数のプロダクトチームに入り込む embedded 型のイネーブリング担当として従事している。「ユーザー価値のデリバリー最大化」を目標に、その手段として SLI/SLO の策定、エラーの自動トリアージ、開発生産性の向上に取り組んでいる。

- 症状検索エンジン「ユビー」(約 1,000 万 MAU)の Rails から Node.js(Nest.js + GraphQL)へのリアーキテクトにて実装の中核を担い、移行実装・負荷試験・パフォーマンスチューニングをリード
  - 移行で守るべき性能基準を移行元のプロダクトチームと合意した上で、k6 による負荷試験基盤とシナリオを整備。データ量が多いケースでのみ顕在化する性能退行など、ユニットテストでは検出できない問題を移行前に解消した
  - そこで得られた知見を社内 ISUCON として展開しつつ移行を完了させ、ユーザー体感としての質問間レイテンシを中央値で従来の約 40% にまで短縮した
- LLM バッチ処理基盤の再構成。LLM に渡す情報を整理する前処理レイヤーを導入し、過去の実行ログをもとに判断できる情報量を増やすことでトークン消費を約 40% 削減。処理量の増大によるトークン利用上限への抵触を回避しつつ、再実行を容易にする設計とすることでデリバリーの確実性を高めた
- Sentry のタグをもとに LLM エージェントが本番エラーを担当エンジニアへ届けるトリアージの仕組みを整備し、障害発生率の削減と、特定のブラウザや環境でのみ発生する不具合への対応速度を改善
- Claude Code を用いた開発環境構築の自動化により、オンボーディングの所要時間を 3 日から 30 分程度に短縮
